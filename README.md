## معرفی پروژه

**CRMWP** یک سامانه نرم‌افزاری مستقل، پرسرعت و مدرن برای مدیریت متمرکز فروشگاه‌های مبتنی بر **WooCommerce** و اتوماسیون ارتباط با مشتریان (CRM) است. این نرم‌افزار به صورت یک لایه مدیریتی اختصاصی در کنار فروشگاه کار می‌کند و دسترسی سریع به اطلاعات سفارش‌ها، محصولات، تنوع‌ها، انبار و مشتریان را بدون نیاز به ورود به پیشخوان سنگین وردپرس میسر می‌سازد.

### ویژگی‌های بنیادین ساختاری:
* **پلاگین وردپرس نیست (Not a WordPress Plugin)**: هیچ کدی، فایلی یا پلاگینی در هاست وردپرس یا پوشه `wp-content/plugins` نصب نمی‌شود.
* **خارج از پیشخوان وردپرس اجرا می‌شود**: در ساب‌دامین یا سروری کاملاً مستقل با رابط کاربری بهینه‌شده با Vue 3 اجرا می‌شود و هیچ بار پردازشی به پیشخوان اصلی فروشگاه وارد نمی‌کند.
* **ووکامرس منبع اصلی حقیقت است (WooCommerce is Source of Truth)**: داده‌های هسته تجارت (محصولات، تنوع‌ها، موجودی انبار، سفارش‌ها و اطلاعات پایه مشتریان) مستقیماً از ووکامرس فراخوانی شده و در صورت تغییر، مستقیماً در ووکامرس ذخیره می‌شوند.
* **ارتباط امن صرفاً از طریق استاندارد WooCommerce REST API v3**: ارتباط با فروشگاه صرفاً از بستر شبکه و با کلیدهای امن و احراز هویت کنترل‌شده انجام می‌پذیرد.
* **عدم وابستگی به ران‌تایم‌های سنگین در پروداکشن**: نسخه اجرایی پروداکشن بدون نیاز به Node.js، npm، Docker، Redis یا پردازشگرهای پیچیده، با وب‌سرور استاندارد PHP و MariaDB/MySQL اجرا می‌شود.

## چرا این پروژه ساخته شد؟

مدیریت فروشگاه‌های پرترافیک و پرفروش ووکامرس از طریق پیشخوان پیش‌فرض وردپرس (`/wp-admin`) معمولاً با چالش‌های فنی زیر همراه است:

1. **کندی و سنگینی شدید پیشخوان وردپرس**: اجرای همزمان قالب‌های تجاری، افزونه‌های سئو، صفحه‌سازها و ماژول‌های آماری، لود صفحات سفارش‌ها و کاتالوگ محصولات را کند و فرسایشی می‌کند.
2. **فقدان ابزارهای تخصصی CRM در هسته وردپرس**: ووکامرس به عنوان یک موتور فروشگاهی طراحی شده است؛ امکاناتی مانند ایجاد وظایف پیگیری (Tasks)، یادداشت‌های خصوصی تیم فروش، برچسب‌های رنگی چندمنظوره (Tags)، بخش‌بندی پویای مشتریان (Segments) و ثبت لاگ فعالیت‌ها در هسته ووکامرس وجود ندارد.
3. **ریسک بالای دسترسی به کل هاست و قالب**: ایجاد حساب کاربری برای کارشناسان فروش، بازاریاب‌ها، حسابداران یا انبارداران در پیشخوان وردپرس، ریسک تغییرات ناخواسته در تنظیمات، افزونه‌ها یا فایل‌های هسته وردپرس را ایجاد می‌کند.
4. **ویرایش گروهی کند و دشوار محصولات متغیر**: اصلاح قیمت یا موجودی صدها تنوع کالایی (Variations) در پیشخوان ووکامرس بسیار زمان‌بر، مستعد قطعی تایم‌اوت و خطای انسانی است.
5. **نبود مدیریت یکپارچه برای مدیران چندفروشگاهی**: مدیریت همزمان چند فروشگاه آنلاین مجزا نیازمند باز کردن چند تب و لاگین‌های مداوم است، در حالی که در CRMWP با یک کلیک می‌توان فروشگاه فعال را تغییر داد.

## اصول بنیادین و معماری داده‌ها

CRMWP از یک اصل معماری دقیق به نام **تفکیک مالکیت داده‌ها (Data Ownership Segregation)** پیروی می‌کند:

| دامنه داده | منبع حقیقت (Source of Truth) | ذخیره‌سازی محلی در CRMWP | توضیحات فنی |
| :--- | :--- | :--- | :--- |
| **محصولات و کاتالوگ** | WooCommerce | کش موقت (Read Cache) | قیمت، وضعیت، دسته‌بندی و خصوصیات در ووکامرس نگهداری می‌شوند. |
| **تنوع‌های کالایی (Variations)** | WooCommerce | کش موقت (Read Cache) | شناسه، SKU، قیمت‌ها و موجودی هر متغیر مستقیماً از ووکامرس دریافت می‌گردد. |
| **سفارش‌ها و صورت‌حساب** | WooCommerce | کش موقت (Read Cache) | وضعیت، مبالغ، اقلام سبد و آدرس‌های ارسال و فاکتور از ووکامرس مدیریت می‌شوند. |
| **مشتریان (اطلاعات پایه)** | WooCommerce | همگام‌سازی و آینه‌سازی شناسه | نام، ایمیل، شماره تماس، آدرس‌ها و مبالغ خرید مستقیماً با ووکامرس متناظر هستند. |
| **داده‌های CRM (یادداشت‌ها)** | CRMWP Local Database | منبع اصلی | یادداشت‌های محرمانه پشتیبانی و بازاریابی در دیتابیس محلی ذخیره می‌شوند. |
| **برچسب‌ها و سگمنت‌ها (Tags & Segments)** | CRMWP Local Database | منبع اصلی | دسته‌بندی‌های رفتاری و تگ‌های رنگی پرسنل در دیتابیس محلی مدیریت می‌شوند. |
| **وظایف پیگیری (Tasks)** | CRMWP Local Database | منبع اصلی | تسک‌های اختصاص‌یافته به کارشناسان فروش در دیتابیس محلی ذخیره می‌گردند. |
| **کاربران و نقش‌ها (RBAC)** | CRMWP Local Database | منبع اصلی | کاربران پنل CRM کاملاً مستقل از جدول `wp_users` وردپرس هستند. |
| **کلیدهای اتصال و فروشگاه‌ها** | CRMWP Local Database | منبع اصلی (رمزنگاری‌شده) | کلیدهای API و شناسه فروشگاه‌ها با الگوریتم AES-256-CBC نگهداری می‌شوند. |

## معماری فنی و جریان داده

معماری سامانه بر مبنای جریان پردازش یک‌سویه، امن و ایزوله پیاده‌سازی شده است:

```text
┌──────────────┐         HTTPS          ┌───────────────────┐
│              │ ────────────────────>  │    PHP Backend    │
│  Client UI   │   (Session Cookie +    │  (Router, RBAC,   │
│   (Vue 3)    │    X-CSRF-Token)       │   Controllers)    │
│              │ <────────────────────  │                   │
└──────────────┘      JSON Response     └─────────┬─────────┘
                                                  │
                                                  ▼
                                        ┌───────────────────┐
                                        │    WooCommerce    │
                                        │      Adapter      │
                                        │ (cURL, Encrypted) │
                                        └─────────┬─────────┘
                                                  │
                                                  ▼ HTTPS (REST API v3)
                                        ┌───────────────────┐
                                        │    WooCommerce    │
                                        │    Store Core     │
                                        │  (HPOS / Legacy)  │
                                        └───────────────────┘
```

> [!IMPORTANT]
> **قانون امنیتی قطعی**: مرورگر کاربر (Browser) هرگز و تحت هیچ شرایطی به صورت مستقیم به WooCommerce REST API وصل نمی‌شود. تمامی درخواست‌ها ابتدا در بک‌اند CRMWP اعتبارسنجی شده، مجوزهای کاربر بررسی می‌گردند، و سپس آداپتور سرور با استفاده از کلیدهای رمزنگاری‌شده، عملیات را در ووکامرس به انجام می‌رساند. همچنین اتصال مستقیمی به پایگاه‌داده MySQL وردپرس برقرار نمی‌شود.

## آداپتور ووکامرس

کلاس `App\Services\WooCommerceAdapter` به عنوان پل ارتباطی ایزوله، جزئیات ارتباطی ووکامرس را از لایه منطق تجاری CRM جدا می‌کند:
* **مدیریت نشست‌های شبکه و cURL**: پیاده‌سازی کلاینت شبکه مستقل با بررسی کدهای پاسخ HTTP، تایم‌اوت‌های قابل تنظیم و هدرهای استاندارد.
* **احراز هویت بر اساس کلیدهای رمزنگاری‌شده**: خواندن کلیدهای `Consumer Key` و `Consumer Secret` و رمزگشایی متقارن آن‌ها با کلید امنیتی سامانه (`ENCRYPTION_KEY`).
* **مدیریت صفحه‌بندی (Pagination Handling)**: خواندن هدرهای پاسخ `X-WP-Total` و `X-WP-TotalPages` جهت ارائه صفحه‌بندی پایدار در کاتالوگ و لیست سفارش‌ها.
* **ترجمه و فیلتراسیون خطاها**: مدیریت یکپارچه خطاهای ووکامرس (مانند `rest_cannot_read` یا `woocommerce_rest_invalid_id`) و بازگرداندن پاسخ‌های استاندارد ساختاریافته بدون افشای مسیرهای سرور.

## تشخیص و سازگاری با HPOS

قابلیت **High-Performance Order Storage (HPOS)** ووکامرس تحول بزرگی در نحوه نگهداری سفارش‌ها در جداول اختصاصی (`wc_orders`) به جای جدول قدیمی `wp_posts` به همراه دارد.

* **تشخیص بر اساس قابلیت واقعی فروشگاه (Runtime Capability Detection)**: سامانه با ارسال درخواست به روت‌های سیستمی ووکامرس، وضعیت فعال بودن `custom-order-tables` را استعلام می‌کند؛ هیچ‌گونه نسخه هاردکد شده یا حدس فرضی ملاک عمل قرار نمی‌گیرد.
* **شفافیت کامل برای کاربر و لایه UI**: چه فروشگاه از جداول اختصاصی HPOS استفاده کند و چه از ساختار سنتی پست‌های وردپرس، اندپوینت‌ها و خروجی‌های Orders در پنل CRMWP کاملاً یکسان و بدون تغییر باقی می‌مانند.
* **عدم وابستگی به پایگاه‌داده مستقیم وردپرس**: از آنجا که کلیه کوئری‌ها از طریق استاندارد رسمی REST API v3 انجام می‌شوند، تغییرات اسکیما و ارتقای وردپرس هرگز باعث شکست کوئری‌های پنل CRM نمی‌شود.

## معماری چندفروشگاهی

سامانه به گونه‌ای مهندسی شده است که به عنوان یک هاب مرکزی توانایی اتصال به چندین فروشگاه آنلاین مجزا را دارا باشد:
* **موجودیت فروشگاه (Store Entity)**: هر فروشگاه دارای شناسه مستقل، نام، دامنه، وضعیت اتصال، تایم‌زون مجزا، واحد پول (`IRT`, `IRR`) و کلیدهای رمزنگاری‌شده اختصاصی است.
* **ماتریس دسترسی کاربر-فروشگاه (`user_stores`)**: هر کاربر سامانه می‌تواند به یک یا چند فروشگاه مشخص دسترسی داشته باشد یا توسط مدیر سیستم دسترسی‌های او محدود شود.
* **ایزولاسیون کامل کش و داده‌ها (Context Isolation)**: تمامی کلیدهای کش در حافظه و فایل با پیشوند اختصاصی فروشگاه (`store:{id}:...`) ایزوله می‌شوند تا از تداخل داده‌های دو فروشگاه جلوگیری گردد.
* **سوئیچر فروشگاه در هدر (Store Switcher)**: جابجایی بین فروشگاه‌ها بدون نیاز به لاگ‌اوت و از طریق هدر بالای صفحه انجام می‌شود؛ در زمان سوئیچ، کل Context کلاینت و هدر `X-Store-ID` بازنشانی می‌گردند.

## احراز هویت و امنیت نشست

سیستم ورود و شناسایی بر مبنای استاندارد کوکی سشن سرور (Stateful Session Authentication) پیاده‌سازی شده است:
* **مدیریت سشن محلی**: با کوکی اختصاصی `crmwp_session` با فلگ‌های امنیتی `HttpOnly`, `SameSite=Lax` و کنترل فعال بودن HTTPS با پارامتر `SESSION_SECURE`.
* **رمزنگاری کلمه‌های عبور**: با الگوریتم استاندارد Bcrypt و ضریب کاربری ایمن (`PASSWORD_BCRYPT`).
* **محافظت در برابر حملات جعل درخواست (CSRF Protection)**: تولید توکن یکتای سشن از طریق `/api/v1/auth/csrf` و اعتبارسنجی سخت‌گیرانه در میدلور `CsrfMiddleware` برای کلیه متدهای تغییردهنده (`POST`, `PUT`, `PATCH`, `DELETE`).
* **کنترل نرخ درخواست و مقابله با Brute-Force**: میدلور `RateLimitMiddleware` روی اندپوینت ورود (`/api/v1/auth/login`) محدودیت ۵ تلاش در دقیقه به ازای هر IP را اعمال می‌کند.

## کنترل دسترسی چندسطحی

یک سیستم کنترل دسترسی نقش‌محور (RBAC) مبتنی بر ۵ جدول دیتابیس در هسته نرم‌افزار فعال است:

### ۶ نقش پیش‌فرض تعریف‌شده:
1. **مدیر کل (Admin)**: دسترسی نامحدود به تمامی بخش‌ها، کاربران، تنظیمات، کران‌جاب، لاگ‌ها و پیکربندی فروشگاه‌ها.
2. **مدیر فروشگاه (Manager)**: مدیریت کامل محصولات، سفارش‌ها، مشتریان، انبارداری و عملیات گروهی بدون دسترسی به تغییرات زیرساختی سامانه.
3. **کارشناس فروش (Sales Agent)**: ثبت و مشاهده سفارش‌ها، یادداشت‌گذاری، ایجاد وظایف و بررسی پروفایل مشتریان.
4. **کارشناس پشتیبانی (Support Agent)**: مشاهده سفارش‌ها و مشتریان، ثبت تسک‌ها و یادداشت‌های پشتیبانی بدون امکان تغییر قیمت‌ها یا حذف اقلام.
5. **انباردار (Inventory Clerk)**: دسترسی اختصاصی به مدیریت موجودی، هشدارهای کمبود کالا و اصلاح وضعیت انبار.
6. **مشاهده‌گر (Viewer)**: دسترسی صرفاً خواندنی (Read-Only) به گزارش‌ها و لیست‌ها بدون امکان ویرایش.

### دسته‌بندی مجوزهای سیستم (Permission Categories):
* `users.*`: ایجاد، ویرایش، حذف و مدیریت نقش کاربران.
* `stores.*`: افزودن، تست اتصال و ویرایش اطلاعات فروشگاه‌ها.
* `orders.*`: مشاهده، تغییر وضعیت، ثبت یادداشت و بازپرداخت سفارش‌ها.
* `products.*`: ایجاد، ویرایش قیمت‌ها، حذف و کاتالوگ محصولات و تنوع‌ها.
* `customers.*`: مشاهده مشخصات، تحلیل خرید و ویرایش اطلاعات مشتریان.
* `inventory.*`: ویرایش موجودی و تنظیم آستانه‌های کسری انبار.
* `bulk.*`: اجرای عملیات گروهی، ایجاد پیش‌نمایش و لغو تغییرات (Undo).
* `crm.*`: مدیریت یادداشت‌ها، برچسب‌ها، سگمنت‌ها و تسک‌ها.
* `settings.*`: مدیریت کش شیء، وب‌هوک‌ها و پیکربندی‌های کلی سیستم.
* `reports.*`: مشاهده گزارش‌های فروش و خروجی‌های تحلیلی.

## ساختار هدر و امکان حمایت مالی

هدر سامانه با استانداردهای مدرن SaaS بازآرایی و پولیش شده است:
* **حذف خط عمودی مزاحم (Vertical Divider)**: خط تفکیک‌کننده عمودی که کنار بخش کاربر قرار داشت، به شکل ساختاری از کدهای هدر حذف شد.
* **آواتار محلی بدون Gravatar**: هیچ درخواستی به سرورهای خارجی `gravatar.com` ارسال نمی‌شود. در صورت عدم وجود تصویر پروفایل، از نماد بومی `ProfileCircle` استفاده می‌شود.
* **تاریخ شمسی و ساعت زنده**: نمایش تاریخ جاری با ارقام و تقویم فارسی جلالی و ساعت زنده متصل به تایم‌زون معتبر فروشگاه (`Asia/Tehran`).
* **سیستم حمایت مالی اختیاری (Donate System)**:
  * دکمه زیبا و مینیمال «♡ حمایت» در مجاورت مرکز اعلان‌ها (`[Donate] [Notifications]`).
  * اطلاعات حمایت از طریق متغیرهای محیطی در بک‌اند کنترل می‌شوند و از نقطه انتهایی `GET /api/v1/system/donate` فراخوانی می‌گردند (عدم وجود شماره کارت در سورس یا گیت).
  * مودال رسمی شامل: نام گیرنده (`کمک مالی به حسین محمدپور`)، شماره کارت بانکی با نمایش فاصله‌دار و فارسی (`۶۲۱۹   ۸۶۱۹   ۳۱۹۶   ۵۴۰۳`)، دکمه کپی در کلیپ‌بورد با تایید بصری («کپی شد ✓»)، ایمیل پشتیبانی و پیوند مخزن گیت‌هاب.

> [!CAUTION]
> **نکته امنیتی بسیار مهم**: شماره کارت بانکی یک متغیر محرمانه است و هرگز در سورس‌کد، فرانت‌اند استاتیک یا مخزن عمومی گیت مستند نمی‌شود. مقداردهی آن صرفاً از طریق متغیر محیطی سرور (`DONATE_CARD_NUMBER`) صورت می‌پذیرد.

## موتور ویرایش گروهی پیشرفته

یکی از قدرتمندترین ابزارهای CRMWP، موتور عملیات گروهی بر روی محصولات و تنوع‌ها است:
* **دامنه عملیات (Scope Selection)**: امکان اعمال تغییرات روی «فقط محصولات والد»، «فقط تنوع‌های کالایی» یا «هر دو».
* **عملیات‌های قابل اجرا**:
  * افزایش یا کاهش درصدی قیمت‌ها (مثلاً: افزایش ۱۰٪ قیمت کلیه کالاهای یک دسته‌بندی).
  * افزایش یا کاهش مبلغ ثابت.
  * تنظیم مقدار مشخص برای قیمت عادی یا فروش ویژه.
  * ویرایش وضعیت موجودی (موجود، ناموجود، پیش‌خرید).
  * تغییر وضعیت انتشار کالا (منتشرشده، پیش‌نویس).
  * افزودن پیشوند یا پسوند به SKU اقلام.
* **پردازش دسته‌ای ایمن (Chunked Batching)**: پردازش خودکار در دسته‌های ۵۰تایی با نمایش نوار پیشرفت زنده برای پیشگیری از تایم‌اوت هاست‌های اشتراکی.
* **شبیه‌سازی و پیش‌نمایش قبل از اعمال (Dry-Run Preview)**: مشاهده دقیق قیمت‌های قبل و بعد از تغییر و تعداد رکوردهای تحت تأثیر قبل از ثبت نهایی.
* **قابلیت بازگردانی تغییرات (Undo Engine)**: ذخیره وضعیت پیشین در جدول `bulk_operation_items` جهت بازگرداندن تغییرات در صورت بروز خطای کاربری.

## میز کار CRM

امکاناتی فراتر از یک فروشگاه‌ساز که برای تیم‌های پشتیبانی و فروش طراحی شده‌اند:
* **یادداشت‌های مشتری (Customer Notes)**: ثبت مذاکرات تلفنی، علایق خریدار و توافقات تیم پشتیبانی با ذکر نام ثبت‌کننده و زمان دقیق.

* **مدیریت وظایف تیم (Tasks)**: تعریف وظیفه با عنوان، تاریخ سررسید، اولویت (کم، متوسط، فوری)، اختصاص به کاربر پنل و اتصال مستقیم به مشتری یا سفارش خاص.

## وب‌هوک‌ها، امضای HMAC و همگام‌سازی

* **اتصال آنی از طریق وب‌هوک**: امکان دریافت لحظه‌ای رخدادهای `order.created`, `order.updated`, `customer.created` و `product.updated` از ووکامرس.
* **اعتبارسنجی امضای امنیتی HMAC-SHA256**: هر پی‌لود دریافتی با کلید سر فروشگاه تطبیق داده شده و درخواست‌های فاقد امضای معتبر رد می‌شوند.
* **تضمین تکرارناپذیری (Idempotency)**: ثبت شناسه پیام‌های دریافتی برای جلوگیری از پردازش تکراری رخدادها در صورت ارسال مجدد توسط وردپرس.
* **فرآیند مغایرت‌گیری دوره‌ای (Reconciliation)**: تسک پس‌زمینه کران‌جاب جهت بررسی و همگام‌سازی سفارش‌هایی که به دلیل قطعی موقت هاست از طریق وب‌هوک دریافت نشده‌اند.

## سیستم کش دوگانه: شیء و فایل

CRMWP دارای معماری کش دوگانه منعطف است تا هم روی هاست‌های اشتراکی ساده و هم سرورهای پرسرعت اختصاصی بهترین بازدهی را داشته باشد:

```text
┌────────────────────────────────────────────────────────┐
│                      Cache Facade                      │
├───────────────────────────┬────────────────────────────┤
│   Local File Cache        │    Distributed Object Cache│
│   (storage/cache/)        │    (Memcached / Memcache)  │
│   - بدون نیاز به افزونه    │    - پشتیبانی از TCP       │
│   - فعال به صورت پیش‌فرض    │    - پشتیبانی از Unix Sock │
└───────────────────────────┴────────────────────────────┘
```

### ۱. کش مبتنی بر فایل (File Cache):
* سیستم کش بومی با سریال‌سازی امن و زمان انقضای دقیق روی فایل‌های دیسک در مسیر `storage/cache/`.
* ۱۰۰٪ مستقل و بدون نیاز به نصب هرگونه اکستنشن خاص روی سرور.

### ۲. کش شیء (Object Cache - Memcached):
* پشتیبانی کامل از هر دو حالت اتصال:
  * شبکه **TCP/IP** (مانند: `127.0.0.1:11211`)
  * سوکت یونیکس **Unix Domain Socket** (مانند: `/var/run/memcached/memcached.sock` برای سرعت بالاتر روی سرورهای لینوکسی).
* **تست اتصال واقعی ۴ مرحله‌ای**: در زمان فشردن دکمه تست در پنل، مراحل زیر به صورت واقعی اجرا می‌شوند:
  ```text
  اتصال به سرور (Connect) ──> ثبت کلید موقت (Set) ──> خواندن مقدار (Get) ──> تایید صحت و حذف (Delete)
  ```
* **محاسبه واقعی ضریب اصابت (Hit Ratio)**:
  $$\text{Hit Ratio} = \frac{\text{Hits}}{\text{Hits} + \text{Misses}} \times 100$$
  اگر ترددی ثبت نشده باشد، وضعیت **«بدون داده»** اعلام می‌شود؛ هرگز درصد فرضی یا ساختگی تولید نمی‌گردد.

## سخت‌سازی امنیتی و حفاظت از اطلاعات

1. **رمزنگاری در حالت سکون (Encryption at Rest)**: کلیدهای Consumer Secret ووکامرس در جدول `stores` با متد **AES-256-CBC** به همراه هش اعتبارسنجی HMAC نگهداری می‌شوند.
2. **سیاست امنیت محتوا (Content Security Policy - CSP)**: هدرهای سخت‌گیرانه CSP برای مسدودسازی اجرای اسکریپت‌های ناشناس و مجاز دانستن دامنه‌های تصاویر فروشگاه متصل.
3. **عدم افشای سکرت‌ها در لاگ‌ها**: کلیدهای اتصال، شماره کارت، پسوردها و توکن‌ها قبل از ثبت در لاگ‌ها پالایش و پنهان می‌شوند.
4. **محدودسازی نرخ درخواست (Rate Limiting)**: کنترل درخواست‌های ورودی به API جهت مقابله با حملات DoS و Brute-Force.
5. **کوکی‌های سشن ایمن**: اعمال پرچم‌های `HttpOnly`, `SameSite=Lax` جهت پیشگیری از سرقت نشست و حملات XSS.

## پیش‌نیازهای نرم‌افزاری و سخت‌افزاری

### ۱. سمت سرور (Server Runtime):
* **نسخه PHP**: حداقل `PHP 8.2.0` (پیشنهادی: `PHP 8.3` یا `PHP 8.4`).
* **پایگاه‌داده**: `MariaDB 10.6+` / `11.x` یا `MySQL 8.0+` با انجین InnoDB و Charset `utf8mb4`.
* **وب‌سرور**: `Apache 2.4+` (با فعال بودن `mod_rewrite`)، `Nginx` یا `LiteSpeed`.
* **اکستنشن‌های الزامی PHP**:
  * `pdo` و `pdo_mysql`
  * `openssl`
  * `mbstring`
  * `curl`
  * `json`
  * `session`
  * `fileinfo`
* **اکستنشن‌های اختیاری (جهت شتاب‌بخشی)**:
  * `memcached` یا `memcache` (برای اتصال کش شیء)
  * `apcu`
  * `zip`

### ۲. سمت فروشگاه مبدأ (WooCommerce Store):
* وردپرس نسخه `6.2+`
* ووکامرس نسخه `7.9+` (تست‌شده تا نسخه `8.x` و سازگار با `11.x`)
* فعال بودن پروتکل امن SSL (`HTTPS`)
* دسترسی باز به روت‌های رسمی `/wp-json/wc/v3/` بدون انسداد توسط فایروال

## راهنمای گام‌به‌گام نصب و راه‌اندازی

سامانه مجهز به یک نصب‌کننده تحت وب ۴ مرحله‌ای (Web Installer) و ابزار خط فرمان است:

### روش اول: نصب از طریق رابط وب (پیشنهادی)
1. بسته انتشار `CRM-Production-Release-1.1.0.zip` را از بخش [Releases در گیت‌هاب](https://github.com/satinbest/crmwp/releases/latest) دریافت کرده و در هاست خود آپلود و از حالت فشرده خارج نمایید.
2. مسیر Document Root وب‌سرور یا ساب‌دامین را بر روی پوشه `public/` تنظیم کنید.
3. یک پایگاه‌داده خالی MariaDB/MySQL ایجاد نمایید.
4. در مرورگر به آدرس دامنه مراجعه کنید (سیستم به طور خودکار به `/install` هدایت می‌شود).
5. **مرحله ۱**: بررسی پیش‌نیازهای سرور، نسخه‌های PHP و مجوزهای پوشه `storage/`.
6. **مرحله ۲**: ورود مشخصات اتصال پایگاه‌داده، تست اتصال و اجرای خودکار ۱۹ مایگریشن اسکیما.
7. **مرحله ۳**: ایجاد حساب کاربری مدیر کل (Admin) با کلمه عبور ایمن.
8. **مرحله ۴**: ورود دامنه فروشگاه ووکامرس، `Consumer Key` و `Consumer Secret` و تست اتصال به فروشگاه.
9. اتمام نصب و ورود به پیشخوان CRM.

### روش دوم: نصب سریع از طریق خط فرمان (CLI)
در صورتی که دسترسی SSH به سرور دارید:
```bash
# کپی فایل محیطی
cp .env.example .env

# ویرایش اطلاعات دیتابیس در .env
nano .env

# اجرای اسکریپت نصب و مایگریشن‌ها
php cli.php install
```

### تنظیم کران‌جاب خودکار (Cron Job)
جهت اجرای وظایف پس‌زمینه، تسک‌های همگام‌سازی و مغایرت‌گیری، کران‌جاب را به صورت اجرای هر ۱ الی ۵ دقیقه تنظیم کنید:
```bash
# اجرای کران از طریق خط فرمان سرور
* * * * * php /path/to/crmwp/cron.php >/dev/null 2>&1

# یا اجرای وب‌کرون امن از طریق URL با سکرت اختصاصی
*/5 * * * * curl -s "https://crm.yourdomain.com/api/v1/system/cron?secret=YOUR_CRON_SECRET" >/dev/null 2>&1
```

## ساختار پایگاه‌داده محلی

پایگاه‌داده محلی سامانه از ۱۹ مایگریشن استاندارد تشکیل یافته است:
* `users`: حساب‌های کاربری پرسنل و مشخصات ورود.
* `roles` و `permissions`: تعاریف نقش‌های کاربری و ماتریس مجوزها.
* `user_roles` و `role_permissions`: جداول واسط نقش‌ها و دسترسی‌ها.
* `stores`: اطلاعات فروشگاه‌های ووکامرس و کلیدهای رمزنگاری‌شده API.
* `user_stores`: جدول واسط تخصیص فروشگاه به هر کاربر پنل.
* `customer_notes`: یادداشت‌های محرمانه پشتیبانی پیرامون هر مشتری.
* `tags` و `customer_tags`: برچسب‌های رنگی و تخصیص آن‌ها به خریداران.
* `segments` و `customer_segments`: گروه‌بندی‌های پویا و هوشمند مشتریان.
* `tasks`: وظایف کاری پرسنل با اولویت، مهلت انجام و ارتباط با سفارش‌ها.
* `activities`: تایم‌لاین رویدادهای عملیاتی مشتریان و فروشگاه.
* `notifications`: پیام‌ها و هشدارهای درون‌برنامه‌ای کاربران.
* `audit_logs`: لاگ‌های امنیتی و مدیریتی سطح بالا.
* `bulk_operations` و `bulk_operation_items`: تاریخچه ویرایش‌های گروهی محصولات، وضعیت اقلام و داده‌های بازگردانی (Undo).
* `webhooks` و `webhook_logs`: تنظیمات وب‌هوک‌های دریافتی و تاریخچه درخواست‌های ورودی.
* `sync_logs`: گزارش‌های دوره‌ای همگام‌سازی و مغایرت‌گیری.
* `automations` و `automation_runs`: قوانین اتوماسیون گردش کار و تاریخچه اجرای سناریوها.

## توسعه، ساخت و انتشار پروداکشن

### دستورات محیط توسعه (Development Workflow)
در صورتی که قصد توسعه کدهای فرانت‌اند و کامپوننت‌های Vue را دارید:
```bash
# نصب پکیج‌های توسعه فرانت‌اند
npm install

# اجرای سرور توسعه Vite با HMR
npm run dev

# بررسی سلامت بک‌اند با سرور داخلی PHP
php -S 127.0.0.1:8000 -t public
```

### ساخت بیلد نهایی فرانت‌اند (Production Build)
```bash
npm run build
```
این دستور کدهای Vue و استایل‌های Tailwind را بهینه‌سازی کرده و فایل‌های کامپایل‌شده را داخل `public/assets/` قرار می‌دهد.

### بسته‌بندی پکیج انتشار سرور (Release Packaging)
```bash
php build_release.php
```
این اسکریپت به صورت خودکار:
1. پوشه تمیز `release/app_package/` را ایجاد می‌کند.
2. کدهای بک‌اند، دارایی‌های کامپایل‌شده فرانت‌اند، و کتابخانه‌های بهینه‌شده `vendor/` را کپی می‌کند.
3. اقلام غیرمجاز (`.git`, `node_modules`, `tests`, `.env`, لاگ‌های محلی) را حذف می‌کند.
4. بسته فشرده استاندارد **`CRM-Production-Release-1.1.0.zip`** را تولید کرده و کد هش SHA-256 آن را محاسبه می‌نماید.
