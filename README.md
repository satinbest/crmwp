## معرفی پروژه

**CRMWP** یک اپلیکیشن مستقل، سریع و مدرن برای مدیریت سفارش‌ها، محصولات، مشتریان و عملیات ارتباط با مشتریان (CRM) در فروشگاه‌های مبتنی بر **WooCommerce** است.

### ویژگی‌های بنیادین ساختاری:
* **یک پلاگین وردپرس نیست (Not a WordPress Plugin)**: نیازی به نصب هیچ پلاگین، اسکریپت یا کدی در وردپرس ندارد.
* **درون پیشخوان وردپرس اجرا نمی‌شود**: یک پنل مستقل و اختصاصی با رابط کاربری مدرن Vue 3 است که بار پردازشی را از سرور اصلی فروشگاه خارج می‌کند.
* **یک اپلیکیشن مستقل (Standalone Application) است**: دارای وب‌سرور، پایگاه‌داده، مسیریاب، سیستم احراز هویت و کش مستقل است.
* **ووکامرس منبع اصلی حقیقت است (WooCommerce is Source of Truth)**: کلیه اطلاعات محصولات، تنوع‌ها، موجودی، سفارش‌ها و اطلاعات پایه مشتریان مستقیماً از ووکامرس فراخوانی می‌شوند.
* **ارتباط امن صرفاً از طریق استاندارد WooCommerce REST API v3**: تعاملات با استفاده از کلیدهای رمزنگاری‌شده API صورت می‌گیرد.
* **جایگزین بهینه برای عملیات روزمره WP-Admin**: مدیران، کارشناسان فروش، پشتیبانان و انبارداران می‌توانند امور روزمره را بدون نیاز به ورود به داشبورد سنگین وردپرس با سرعت بسیار بالاتر انجام دهند.

## چرا این پروژه ساخته شد؟

مدیریت روزمره یک یا چند فروشگاه ووکامرس پرمخاطب مستقیماً از طریق پیشخوان وردپرس (`/wp-admin`) با چالش‌های فنی و عملیاتی متعددی همراه است:

1. **کندی و سنگینی پیشخوان وردپرس**: اجرای افزونه‌های متعدد، ابزارهای سئو، صفحه‌سازها و اسکریپت‌های تحلیلی، لود صفحات سفارش‌ها و محصولات را در وردپرس کند می‌کند.
2. **فقدان ابزارهای حرفه‌ای CRM در هسته ووکامرس**: ووکامرس برای فروش کالا طراحی شده است، نه برای وظایف پیگیری مشتریان (Tasks)، برچسب‌گذاری چندرنگ (Tags)، بخش‌بندی رفتاری (Segments)، یادداشت‌های خصوصی تیم فروش و خط زمانی فعالیت‌ها (Activity Timeline).
3. **ریسک بالای دسترسی به کل وردپرس**: دادن دسترسی پنل به پرسنل پشتیبانی، انبارداری یا فروشندگان، ریسک دسترسی ناخواسته به تنظیمات قالب، افزونه‌ها یا سورس سایت را به همراه دارد.
4. **ضعف در ویرایش گروهی محصولات و تنوع‌ها**: ویرایش سریع قیمت‌ها یا موجودی صدها تنوع کالایی (Variations) در پیشخوان ووکامرس زمان‌بر و مستعد خطاست.
5. **چالش مدیریت چند فروشگاه همزمان**: مدیرانی که چندین فروشگاه آنلاین مجزا دارند، باید مدام بین پنل‌های مختلف جابجا شوند.

**CRMWP** با ارائه یک لایه کاربردی مجزا، این مسائل را بدون نیاز به تغییر در ساختار سایت مبدأ حل می‌کند.

## اصول بنیادین طراحی

```
┌────────────────────────────────────────────────────────────────────────┐
│                          CORE PRINCIPLES                               │
├──────────────────────────┬──────────────────────────┬──────────────────┤
│ WooCommerce = Truth      │ No Direct DB Connection  │ Shared-Hosting   │
│ مشتری، سفارش، کالا از    │ بدون اتصال مستقیم به      │ اجرای مستقل روی  │
│ ووکامرس خوانده می‌شود.   │ دیتابیس wp_posts و HPOS. │ هاست‌های معمول. │
└──────────────────────────┴──────────────────────────┴──────────────────┘
```

1. **WooCommerce is the Source of Truth**:
   اطلاعات پایه سفارش‌ها، مشتریان، کاتالوگ محصولات، تنوع‌ها و موجودی انبار متعلق به ووکامرس است و در این سامانه بدون دلیل موجه کپی مضاعف (Duplicate) نمی‌شود.
2. **No Direct WooCommerce Database Access**:
   این سامانه **هرگز** مستقیماً به MySQL/MariaDB وردپرس متصل نمی‌شود و به جداول `wp_posts`، `wp_postmeta`، جداول HPOS (`wp_wc_orders`) یا ساختارهای داخلی پایگاه‌داده سایت مقصد وابستگی ندارد. تمامی تبادلات از طریق لایه استاندارد **WooCommerce REST API** انجام می‌شود.
3. **Architecture Standalone**:
   سیستم کاملاً خوداتکا (Self-Contained) بوده و کدهای آن به صورت ایزوله اجرا می‌شوند.
4. **Shared Hosting Friendly**:
   معماری بک‌اند و فرانت‌اند به شکلی بهینه‌سازی شده که روی اقتصادی‌ترین هاست‌های اشتراکی لینوکسی (cPanel, DirectAdmin, Plesk) با وب‌سرور Apache/LiteSpeed بدون نیاز به دسترسی Root، داکر یا دیمن‌های اختصاصی قابل اجرا باشد.

| :--- | :--- | :--- |
| **مشتریان (Customers)** | **WooCommerce** | نام، ایمیل، شماره تماس، آدرس‌های صورتحساب و ارسال مستقیماً از ووکامرس خوانده می‌شوند. |
| **سفارش‌ها (Orders)** | **WooCommerce** | وضعیت سفارش، اقلام، مالیات، حمل‌ونقل و تراکنش‌ها در ووکامرس نگهداری و مدیریت می‌شوند. |
| **محصولات و تنوع‌ها (Products & Variations)** | **WooCommerce** | عنوان، قیمت‌ها، SKU، دسته‌بندی‌ها، ویژگی‌ها و موجودی انبار مستقیماً متعلق به ووکامرس است. |
| **یادداشت‌های CRM (Customer Notes)** | **CRMWP** | یادداشت‌های محرمانه تیم فروش روی پروفایل مشتری درون دیتابیس محلی ذخیره می‌شوند. |
| **برچسب‌های مشتری (Tags)** | **CRMWP** | برچسب‌های تفکیک مشتریان (VIP، خوش‌حساب، پیگیری ویژه) اختصاصی این سامانه است. |
| **بخش‌بندی‌ها (Segments)** | **CRMWP** | گروه‌بندی‌های پویا بر اساس الگوهای خرید مشتریان به صورت کوئری‌های محلی تحلیل می‌شوند. |
| **وظایف پیگیری (Tasks)** | **CRMWP** | تسک‌های ارجاع‌شده به اپراتورها همراه با مهلت انجام و وضعیت در دیتابیس CRM ثبت می‌شوند. |
| **خط زمانی فعالیت‌ها (Activities)** | **CRMWP** | رخدادهای سیستمی و تعاملات کاربران با مشتریان به صورت تایم‌لاین ثبت می‌گردند. |
| **اعلان‌ها و رویدادها (Notifications)** | **CRMWP** | مرکز هشدارها و اعلان‌های داخلی برای رویدادهای مهم سفارش و انبار. |
| **لاگ‌های حسابرسی (Audit Logs)** | **CRMWP** | تاریخچه تغییرات حساس و ویرایش‌های گروهی جهت نظارت امنیتی ذخیره می‌شوند. |
| **قوانین اتوماسیون (Automations)** | **CRMWP** | تعاریف سناریوهای شرطی، تریگرها، اکشن‌ها و سابقه اجراها درون دیتابیس CRM قرار دارد. |
| **کاربران و دسترسی‌ها (RBAC)** | **CRMWP** | کاربران پنل، نقش‌ها، مجوزها و فروشگاه‌های منتسب به هر کاربر کاملاً محلی مدیریت می‌شوند. |

## قابلیت‌های پیاده‌سازی‌شده

تمامی قابلیت‌های زیر در سورس‌کد پروژه موجود، فعال و تست‌شده می‌باشند:

### ۱. احراز هویت و امنیت نشست (Authentication & Session)
* ورود و خروج امن مبتنی بر PHP Native Session امن‌شده با فلگ‌های `HttpOnly`، `SameSite=Lax` و `Secure`.
* سیستم ضد Brute-Force خودکار با محدودیت ۵ تلاش در هر ۶۰ ثانیه به ازای هر IP.
* استفاده از هش رمزنگاری مدرن `PASSWORD_BCRYPT` با فاکتور هزینه (Cost) ۱۲.
* تعویض شناسه نشست بلافاصله پس از لاگین (`Session::regenerate`) جهت جلوگیری از حملات Session Fixation.

### ۲. مدیریت کاربران و نقش‌ها (Users & Granular RBAC)
* ماتریس کنترل دسترسی چندسطحی مبتنی بر مجوزهای ریزدانه (Granular Permissions).
* ۶ نقش سیستمی از پیش‌تعریف‌شده:
  1. `administrator` (مدیر ارشد سامانه)
  2. `store_manager` (مدیر فروشگاه)
  3. `sales_agent` (کارشناس فروش)
  4. `support_agent` (کارشناس پشتیبانی)
  5. `inventory_manager` (مدیر انبار و زنجیره تأمین)
  6. `readonly_auditor` (حسابرس و ناظر فقط خواندنی)
* امکان تعریف نقش‌های سفارشی نامحدود، کپی‌برداری از نقش‌ها و تخصیص مستقیم دسترسی‌ها.
* مکانیزم محافظت سخت‌افزاری از آخرین مدیر ارشد فعال سیستم (ممانعت از حذف، غیرفعال‌سازی یا خلع نقش).

### ۳. مدیریت چندفروشگاهی (Multi-Store Management)
* اتصال نامحدود به فروشگاه‌های مستقل ووکامرس.
* تست فوری اتصال و اعتبارسنجی دسترسی‌ها پیش از ذخیره‌سازی.
* سوئیچر سریع فروشگاه در فرانت‌اند با ایزولاسیون کامل داده‌ها، کش و لاگ‌ها (Anti-IDOR).
* تشخیص پویای قابلیت‌های فروشگاه (Capability Detection) اعم از وضعیت HPOS، نسخه ووکامرس و وردپرس، واحد پول و وضعیت وب‌هوک‌ها.

### ۴. مدیریت مشتریان (Customer Management)
* فهرست مشتریان با قابلیت جستجوی سریع براساس نام، ایمیل، نام کاربری یا شماره تماس.
* نمایش جزئیات کامل مشتری همراه با شاخص ارزش طول عمر (LTV) و تاریخچه کلیه سفارش‌ها.
* افزودن یادداشت‌های خصوصی تیم فروش با برچسب زمانی.
* برچسب‌گذاری چندرنگ (Tags) روی مشتریان.
* ایجاد تسک‌های پیگیری با اولویت‌بندی و موعد تحویل برای هر مشتری.
* خط زمانی یکپارچه فعالیت‌های کاربر و تعاملات مشتری.

### ۵. مدیریت سفارش‌ها (Order Management)
* جدول جامع سفارش‌ها با فیلترهای پیشرفته بر اساس وضعیت، بازه تاریخی، شناسه مشتری و جستجوی شماره سفارش.
* نمایش شناسه‌های سفارش، مبالغ اقلام، آدرس صورتحساب، روش‌های پرداخت و حمل‌ونقل.
* شناسایی و پشتیبانی از وضعیت‌های سفارشی سفارش (Custom Order Statuses) علاوه بر وضعیت‌های استاندارد ووکامرس.
* تغییر وضعیت تکی و گروهی سفارش‌ها.
* ثبت یادداشت‌های عمومی و خصوصی برای سفارش.
* ثبت مرجوعی (Refund) کامل یا جزئی از طریق API استاندارد.

### ۶. کاتالوگ محصولات و موجودی انبار (Products & Inventory)
* نمایش تفکیک‌شده محصولات ساده (Simple) و محصولات متغیر (Variable).
* مدیریت شاخص‌های انبار: کالاهای ناموجود (Out of Stock)، کم‌موجود (Low Stock) و هشدار آستانه.
* ویرایش مستقیم قیمت عادی، قیمت فروش ویژه، تعداد موجودی و وضعیت انبار در سطح کالا و تنوع.
* مدیریت دسته‌بندی‌ها و برچسب‌های محصولات.

### ۷. بخش‌بندی هوشمند مشتریان (Customer Segments)
* ایجاد بخش‌بندی‌های پویا با شروط متنوع (تعداد سفارش، مجموع مبلغ خرید، شهر، آخرین خرید).
* پیش‌نمایش آنی تعداد و فهرست مشتریان منطبق با فیلترها قبل از ذخیره بخش‌بندی.

### ۸. مرکز اعلان‌ها و فعالیت‌ها (Notifications & Activity Center)
* ثبت هشدارهای لحظه‌ای برای رویدادهای مهم (ثبت سفارش با ارزش بالا، ناموجود شدن کالا، خطای وب‌هوک).
* نمایش شمارنده خوانده‌نشده در بالای صفحه.
* امکان تنظیم ترجیحات اعلان برای هر کاربر بر اساس نوع رویداد.

### ۹. وب‌هوک‌ها و تطبیق داده‌ها (Webhooks & Reconciliation)
* ساخت و تنظیم خودکار وب‌هوک‌های ووکامرس از داخل پنل با یک کلیک.
* بررسی امضای هش HMAC-SHA256 برای تضمین اصالت درخواست‌ها.
* تشخیص و جلوگیری از پردازش رویدادهای تکراری با کلید تحویل (`delivery_id`).
* ابزار مغایرت‌گیری دستی و دوره‌ای برای هماهنگ‌سازی اطلاعات هنگام قطعی اینترنت یا از دست رفتن وب‌هوک.

### ۱۰. موتور اتوماسیون گردش کار (Automation & Workflow Engine)
* سازنده سناریو با تریگرهای متنوع (ایجاد سفارش، تغییر وضعیت سفارش، ثبت مشتری جدید).
* شروط تو در تو و ارزیابی منطقی (AND / OR) روی فیلدهای سفارش و مشتری.
* اقدامات خودکار (ارسال یادداشت، برچسب‌گذاری، ایجاد وظیفه، ثبت اعلان).
* سیستم ایمنی جلوگیری از حلقه بی‌پایان (Loop Prevention) با عمق حداکثر ۵ فراخوانی بازگشتی.
* قابلیت تست سناریو بدون اثرگذاری واقعی (Dry Run Simulation).

ووکامرس ساختار محصولات متغیر را به صورت والد-فرزند سلسله‌مراتبی ذخیره می‌کند:

```text

└───────────────────────────┬────────────────────────────┘
                            │
            ┌───────────────┼───────────────┐
            ▼               ▼               ▼
      ┌───────────┐   ┌───────────┐   ┌───────────┐
      │ Variation │   │ Variation │   │ Variation │
      │   قرمز / M │   │   قرمز / L │   │   آبی / M  │
      │ • شناسه   │   │ • شناسه   │   │ • شناسه   │
      │ • قیمت    │   │ • قیمت    │   │ • قیمت    │
      │ • موجودی  │   │ • موجودی  │   │ • موجودی  │
```

### نحوه تعامل CRMWP با این ساختار:
1. **تشخیص خودکار تنوع‌ها**: سیستم از طریق اندپوینت `/wp-json/wc/v3/products/{parent_id}/variations` کلیه تنوع‌های زیرمجموعه یک محصول متغیر را استخراج می‌کند.
2. **جداسازی منطقی فیلدها**: سیستم می‌داند که فیلدهایی نظیر «دسته‌بندی» و «برچسب» فقط متعلق به والد هستند؛ درحالی‌که فیلدهای «قیمت عادی»، «قیمت ویژه»، «موجودی» و «SKU» می‌توانند در تک‌تک تنوع‌ها مقادیر کاملاً متمایز داشته باشند.
3. **ویرایش انفرادی و تجمعی تنوع‌ها**: امکان مشاهده و ویرایش مشخصات هر تنوع به صورت کاملاً مستقل بدون نیاز به بارگذاری کل محصول در صفحه کاتالوگ.

## موتور عملیات گروهی

موتور عملیات گروهی سامانه (`BulkOperationEngine`) یکی از قدرتمندترین ماژول‌های پیاده‌سازی‌شده در فازهای ۷ و ۱۸ پروژه است:

```text
انتخاب ردیف‌ها
   │
   ▼
محاسبه پیش‌نمایش (POST /bulk-operations/preview)
   │  └── محاسبه دقیق اقلام متأثر، تفکیک والد و تنوع، و مقادیر جدید
   ▼
تأیید کاربر و ارسال شناسه تکرار (idempotency_key)
   │
   ▼
پردازش دسته‌ای تکه‌تکه (Chunking - پیش‌فرض ۲۰ آیتم در هر درخواست)
   │  ├── تعامل مستقیم با اندپوینت استاندارد /variations/batch
   │  ├── مهار خطاهای جزئی (Partial Failures) بدون توقف کل عملیات
   │  └── ثبت پیشرفت به صورت درصد در جدول bulk_operations
   ▼
ثبت در لاگ‌های حسابرسی (Audit Trail)
```

### نهادهای تحت پوشش عملیات گروهی:

#### ۱. محصولات و تنوع‌ها (Products & Variations)
* **انتخاب دامنه هدف (Target Scope)**:
  * `parent`: فقط اعمال روی محصولات ساده و کالاهای والد متغیر.
  * `variations`: فقط اعمال روی تنوع‌های کالایی درون محصولات متغیر انتخاب‌شده.
  * `both`: اعمال هوشمندانه روی هر دو بخش به شکل همزمان.
* **عملیات قیمت**:
  * افزایش یا کاهش درصدی قیمت (`increase_price_percent`, `decrease_price_percent`).
  * افزایش یا کاهش مبلغ ثابت قیمت (`increase_price_amount`, `decrease_price_amount`).
  * تعیین مقدار مشخص قیمت عادی یا قیمت ویژه (`set_regular_price`, `set_sale_price`).
  * حذف سراسری قیمت‌های ویژه و لغو حراج (`clear_sale_price`).
* **عملیات انبار**:
  * تنظیم دقیق موجودی عددی (`set_stock`).
  * افزایش یا کاهش تعداد موجودی فعلی (`increase_stock`, `decrease_stock`).
  * تغییر وضعیت انبار به موجود، ناموجود یا پیش‌خرید (`set_stock_status`).
  * فعال یا غیرفعال کردن مدیریت انبار (`set_manage_stock`).
* **عملیات تاکسونومی و مشخصات**:
  * افزودن یا حذف دسته‌بندی و برچسب (با اعتبارسنجی اعمال صرفاً روی کالای والد).
  * تغییر وضعیت انتشار کالا (`publish`, `draft`, `private`).
  * تنظیم وزن برای محاسبات حمل‌ونقل.

#### ۲. سفارش‌ها (Orders)
* تغییر دسته‌جمعی وضعیت سفارش‌ها (`change_status`) با هماهنگی وضعیت‌های معتبر فروشگاه.
* افزودن یادداشت همگانی خصوصی یا عمومی برای مشتری به کلیه سفارش‌های فیلترشده (`add_note`).

#### ۳. مشتریان (Customers)
* افزودن یا حذف برچسب‌های CRM به گروهی از مشتریان (`add_tag`, `remove_tag`).
* ایجاد همزمان وظیفه پیگیری برای کلیه مشتریان انتخاب‌شده و ارجاع به یک اپراتور مشخص (`create_task`).

## اتصال و همگام‌سازی با ووکامرس

* **عدم اتصال مستقیم کلاینت به ووکامرس**: مرورگر کاربر هرگز مستقیماً با ووکامرس ارتباط برقرار نمی‌کند. تمامی ارتباطات توسط بک‌اند PHP از طریق متدهای امن `cURL` مدیریت می‌شود.
* **محرمانگی کلیدهای دسترسی**: کلیدهای `consumer_key` و `consumer_secret` هرگز در فرانت‌اند افشا نمی‌شوند.
* **رمزنگاری کلیدها در حالت استراحت (Encryption at Rest)**: کلیدهای دسترسی با کلید اختصاصی سرور (`APP_SECRET`) و الگوریتم `AES-256-CBC` همراه با امضای هش `HMAC-SHA256` در پایگاه‌داده ذخیره می‌شوند.
* **تشخیص قابلیت‌ها (Capability Detection)**: به‌جای بررسی پراکنده نسخه‌ها، سیستم متد `CapabilityDetector` را اجرا کرده و قابلیت‌های فروشگاه مقصد را به صورت یک شیء شناسایی می‌کند.
* **سازگاری با HPOS**: شناسایی خودکار High-Performance Order Storage و هماهنگی کامل بدون اختلال در واکشی اطلاعات سفارش.

## مدیریت چندفروشگاهی

سیستم دارای معماری بومی Multi-Store در تمامی لایه‌هاست:

* **شناسه فروشگاه (Store Context)**: هر درخواست به بک‌اند با ارسال هدر `X-Store-Id` یا شناسه مسیر، زمینه فروشگاه فعال را معین می‌سازد.
* **انتساب کاربر به فروشگاه (User-Store Assignment)**: مدیران می‌توانند مشخص کنند که کدام اپراتور یا کارشناس به کدام فروشگاه‌ها دسترسی دارد. دسترسی غیرمجاز بلافاصله با خطای `403 Forbidden` متوقف و ثبت امنیتی می‌شود (Anti-IDOR).
* **جداسازی کش و لاگ‌ها**: تمامی کش‌ها با کلید `store:{id}:...` ثبت شده و هیچ‌گونه تداخل داده‌ای میان دو فروشگاه رخ نمی‌دهد.
* **استقلال شناسه‌ها**: سیستم می‌داند که شناسه‌های سفارش و محصول در ووکامرس صرفاً درون context همان فروشگاه یکتا هستند و دو فروشگاه می‌توانند هر دو محصولی با شناسه `#100` داشته باشند.

## امنیت و حفاظت از داده‌ها

امنیت در این پروژه بر پایه رویکرد **دفاع در عمق (Defense in Depth)** پیاده‌سازی شده است:

```text
Browser Client
   ↓ (Security Headers: CSP, HSTS, X-Frame-Options, X-Content-Type-Options)
Session Validation (Strict Mode, HttpOnly, SameSite=Lax)
   ↓ (Correlation ID generation: req_...)
CSRF Middleware / Rate Limiter
   ↓ (Timing-safe token check, 5 req/min on login)
Authorization & RBAC
   ↓ (Granular permission verification: e.g. orders.view, users.manage)
Store Isolation Context (Anti-IDOR)
   ↓ (Store existence, Active status, User-Store access check)
Service Layer Validation & Sanitization
   ↓ (Strict typing, Whitelisted sorting, Parameter bounding)
Database Layer (PDO MariaDB)
   ↓ (Native prepared statements, utf8mb4, Emulate prepares = false)
Encrypted Rest Storage
   ↓ (AES-256-CBC + HMAC-SHA256 for WooCommerce consumer keys)
External WooCommerce REST API
     (No secrets in client, strict timeouts: 15s read, 8s connect)
```

### استانداردهای شاخص امنیتی:
* **حفاظت در برابر حملات IDOR میان فروشگاه‌ها**: اعتبارسنجی زمینه فروشگاه (`StoreContext`) در تک‌تک کنترلرها مانع از فراخوانی داده‌های فروشگاه دیگر توسط کاربران غیرمجاز می‌شود.
* **حفاظت در برابر حملات تزریق فرمول در CSV**: پاک‌سازی خودکار کاراکترهای خطرناک آغازین (`=`, `+`, `-`, `@`) در فایل‌های خروجی با متد `Security::escapeCsvFormula()`.
* **ماسک‌گذاری داده‌های حساس در لاگ‌ها**: عدم ثبت کلمات عبور، کلیدهای دسترسی API و شماره کارت‌ها در لاگ وب‌هوک و لاگ سیستم.
* **امنیت فایل‌های آپلودی**: پوشه آپلود فایل‌های آواتار دارای فایل `.htaccess` اختصاصی است که اجرای مستقیم اسکریپت‌های PHP را کاملاً مسدود می‌کند.

## معماری و اندپوینت‌های API

کلیه ارتباطات فرانت‌اند با بک‌اند از طریق مسیر پایه زیر صورت می‌گیرد:

```text
/api/v1/...
```

### هدرهای استاندارد درخواست:
* `Content-Type: application/json`
* `Accept: application/json`
* `X-CSRF-TOKEN: <token>` (جهت متدهای POST, PUT, PATCH, DELETE)

## سازگاری با هاست اشتراکی

این پروژه به گونه‌ای معماری شده که با کمترین منابع و بر روی هاست‌های اشتراکی تجاری (Shared Hosting) به راحتی نصب و اجرا شود:

* **بدون نیاز به پکیج‌های خاص سروری**: به نرم‌افزارهای Redis، RabbitMQ، Supervisor، Docker یا دسترسی ریشه (Root Access) نیازی نیست.
* **پشتیبانی کامل از وب‌سرورهای آپاچی و لایت‌اسپید**: فایل‌های بهینه‌سازی‌شده `.htaccess` در روت `public/` و مسیر `storage/` به صورت پیش‌فرض تعبیه شده‌اند.
* **مدیریت فایل و بدون قفل دیتابیس**: سیستم کنترل همزمانی وظایف دوره‌ای از مکانیزم استاندارد قفل فایل با `flock(LOCK_EX | LOCK_NB)` استفاده می‌کند.

## وظایف پس‌زمینه و کران‌جاب

سیستم برای اجرای پردازش‌های غیرهمزمان، سناریوهای اتوماسیون زمان‌بندی‌شده، تطبیق لاگ‌ها و پاک‌سازی داده‌های منقضی‌شده به یک کران‌جاب (Cron Job) تک‌خطی در سرور نیاز دارد:

### دستور استاندارد کران‌جاب (اجرا در هر دقیقه):

```bash
* * * * * cd /path/to/crmwp && php cron.php >> storage/logs/cron.log 2>&1
```

### وظایف تحت مدیریت `cron.php`:
1. **پردازش اتوماسیون‌های زمان‌بندی‌شده**: اجرای سناریوهایی که در صف پردازش زمان‌بندی‌شده قرار دارند (تا سقف ۵۰ عملیات در هر نوبت).
2. **بازیابی عملیات گروهی متوقف‌شده (Stale Recovery)**: شناسایی عملیات‌هایی که به دلیل قطعی غیرمنتظره سرور بیش از ۲ ساعت در وضعیت `processing` معلق مانده‌اند و تغییر وضعیت آن‌ها به `failed`.
3. **پاک‌سازی خودکار و مدیریت چرخه حیات داده‌ها (Data Retention)**: حذف اعلان‌های خوانده‌شده، لاگ‌های وب‌هوک و لاگ‌های تطبیق قدیمی‌تر از ۳۰ روز جهت سبک نگه‌داشتن دیتابیس.
4. **مکانیزم ضد تداخل پردازش (Non-overlapping Lock)**: بهره‌گیری از قفل موقت `storage/locks/cron.lock` جهت جلوگیری از تداخل اجرای دو کران همزمان.

## جریان توسعه و بیلد

فرآیند آماده‌سازی نرم‌افزار از توسعه تا پروداکشن به صورت زیر طراحی شده است:

```text
┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐
│ محیط توسعه      │       │ ساخت فرانت‌اند  │       │ تولید پکیج انتشار │       │ استقرار در سرور │
│ (Development)   │ ───►  │ (Vite Build)    │ ───►  │ (build_release) │ ───►  │ (Production)   │
│ PHP + Node/Vite │       │ npm run build   │       │ php build_...   │       │ بدون نیاز به    │
│ آزمون و کدنویسی │       │ تولید assets    │       │ ایجاد /release  │       │ Node یا Composer│
└─────────────────┘       └─────────────────┘       └─────────────────┘       └─────────────────┘
```

1. **محیط توسعه (Development)**:
   در این محیط از ابزارهایی نظیر `Node.js`، `npm` و `Composer` برای نصب ماژول‌ها و اجرای Vite در حالت پیش‌نمایش زنده استفاده می‌شود.
2. **ساخت خروجی (Build Process)**:
   با اجرای دستور `npm run build`، فرانت‌اند کامپایل شده و در مسیر `public/assets/` قرار می‌گیرد.
3. **تولید بسته نهایی (Release Packaging)**:
   با اجرای اسکریپت `php build_release.php`، بسته نهایی و بدون فایل‌های اضافی توسعه (مانند `node_modules`، `.git`، `tests`) درون پوشه `release/` قرار می‌گیرد.
4. **زمان اجرای پروداکشن (Production Runtime)**:
   نسخه نهایی کاملاً بدون وابستگی به Node.js بوده و روی سرور لینوکس صرفاً با PHP و دیتابیس MariaDB/MySQL اجرا می‌شود.

## راهنمای گام‌به‌گام نصب و راه‌اندازی

برای راه‌اندازی اولیه سامانه می‌توانید از یکی از دو روش زیر استفاده فرمایید:

### روش اول: استفاده از نصب‌کننده گرافیکی تحت وب (پیشنهادی)

1. **انتقال فایل‌ها**: محتویات پوشه انتشار (`release/`) را در هاست آپلود فرمایید.
2. **تنظیم دایرکتوری وب**: مطمئن شوید **Document Root** هاست شما روی پوشه `public/` قرار دارد.
3. **دسترسی نوشتن**: مجوز پوشه `storage/` را روی `775` (یا `755`) تنظیم فرمایید.
4. **ایجاد پایگاه‌داده**: یک دیتابیس MySQL / MariaDB با انکودینگ `utf8mb4` در کنترل‌پنل هاست خود بسازید.
5. **مراجعه به ویزارد نصب**: مرورگر خود را باز کرده و به آدرس زیر مراجعه فرمایید:
   ```text
   https://your-domain.com/install
   ```
6. **طی کردن مراحل چهارگانه**:
   * **مرحله ۱ — بررسی پیش‌نیازها**: بررسی خودکار اکستنشن‌های PHP و دسترسی نوشتن پوشه‌ها.
   * **مرحله ۲ — اتصال دیتابیس**: ورود مشخصات پایگاه‌داده و فشردن دکمه «تست اتصال».
   * **مرحله ۳ — ایجاد حساب مدیر کل**: تعیین نام، نام کاربری، ایمیل و کلمه عبور قدرتمند برای مدیر ارشد.
   * **مرحله ۴ — اجرای خودکار استقرار**: اجرای ۱۸ مایگریشن، ثبت داده‌های پیش‌فرض، تولید خودکار فایل `.env` و فعال‌سازی قفل امنیتی `storage/installed.lock`.

### روش دوم: نصب سریع از طریق خط فرمان (CLI)

در صورتی که به محیط ترمینال (SSH) سرور دسترسی دارید:

```bash
# ۱. کپی کردن نمونه تنظیمات
cp .env.example .env

# ۲. وارد کردن مشخصات دیتابیس در فایل تنظیمات
nano .env

# ۳. اجرای مایگریشن‌های ساختاری
php cli.php migrate

# ۴. ثبت نقش‌ها، مجوزها و کاربر پیش‌فرض اولیه
php cli.php db:seed

# ۵. تنظیم سطح دسترسی
chmod -R 775 storage
```

> **نکته**: اطلاعات حساب پیش‌فرض پس از اجرای سیدر:
> * **نام کاربری**: `admin`
> * **کلمه عبور**: `AdminPassword123!` (پس از اولین ورود، سریعاً آن را در بخش پروفایل تغییر دهید).

## تنظیمات و متغیرهای محیطی

فایل `.env` پیکربندی‌های اصلی سرور را در خود نگهداری می‌کند. نمونه این فایل در مخزن تحت عنوان `.env.example` قرار دارد:

## کارایی، مقیاس‌پذیری و پایش

* **صفحه‌بندی سراسری (Pagination)**: کلیه فهرست‌ها (سفارش‌ها، محصولات، مشتریان، لاگ‌ها) به صورت پیش‌فرض با پارامترهای `page` و `per_page` محدود شده و از بارگذاری فله‌ای اطلاعات در حافظه جلوگیری می‌شود.
* **پردازش دسته‌ای تکه‌ای (Chunking)**: عملیات گروهی سنگین در بسته‌های ۲۰ تایی تقسیم شده تا با سقف زمان اجرای مجاز PHP (`max_execution_time`) و سقف حافظه هاست اشتراکی تداخل پیدا نکند.
* **کش هوشمند فروشگاه**: اطلاعات پایدار نظیر قابلیت‌های ووکامرس و وضعیت‌ها در کش فایل محلی ذخیره می‌شوند تا فراخوانی مکرر شبکه به حداقل برسد.
* **ایندکس‌گذاری دقیق پایگاه‌داده**: تمامی ستون‌های پرکاربرد در جستجو (`store_id`, `status`, `created_at`, `idempotency_key`) دارای ایندکس اختصاصی در مایگریشن‌ها هستند.

## مدیریت خطا و ثبت لاگ

* **شناسه پیگیری یکتا (Correlation ID)**: برای هر درخواست ورودی به سرور، یک شناسه منحصر‌به‌فرد در فرمت `req_66f...` تولید شده و در هدر پاسخ `X-Request-Id` درج می‌گردد. در صورت بروز هر خطایی در سیستم، کاربر صرفاً این کد رهگیری را می‌بیند.
* **محیط بدون افشای اطلاعات (Safe Production Errors)**: در محیط پروداکشن (`APP_DEBUG=false`) استک‌تریس‌ها، اسامی جداول و ساختارهای کد هرگز به کاربر نمایش داده نمی‌شوند و فقط پیام‌های خطای استاندارد بازگردانده می‌شوند.
* **لاگ‌های ایزوله در `storage/logs/`**: خطاهای سیستمی همراه با شناسه پیگیری، زمان، فایل و خط در فایل‌های لاگ روزانه ذخیره می‌شوند. داده‌های حساس مانند رمزها و توکن‌ها قبل از ثبت در لاگ سانسور می‌شوند (`***REDACTED***`).

## نقشه راه آینده

قابلیت‌هایی که برای نسخه‌های بعدی (`v1.1+`) در نظر گرفته شده‌اند و هنوز در نسخه فعلی وجود ندارند:

* [ ] **سیستم صندوق فروشگاهی حضوری (POS Mode)**: رابط کاربری ساده‌شده و سریع جهت ثبت سفارش‌های حضوری در فروشگاه‌های فیزیکی.
* [ ] **اپلیکیشن اختصاصی موبایل**: نسخه PWA پیشرفته و بسته‌های اندروید/iOS برای مدیریت سریع وضعیت انبار با بارکدخوان دوربین.
* [ ] **افزونه‌های دستیار هوش مصنوعی**: تحلیل هوشمند سبد خرید مشتریان و پیشنهاد الگوهای تخفیف بر اساس رفتارهای خرید قبلی.

## محدودیت‌های فنی

برای تصمیم‌گیری صحیح در استقرار، آگاهی از محدودیت‌های فنی زیر ضروری است:

1. **وابستگی به فعال بودن REST API در وردپرس**: ووکامرس مقصد باید امکان پاسخ‌دهی به REST API را داشته باشد و فایروال‌های هاست نباید مسیرهای `/wp-json/wc/v3/` را مسدود کنند.
2. **پروتکل امن SSL (HTTPS)**: ووکامرس برای احراز هویت با کلیدهای Consumer Key استفاده از HTTPS را الزامی می‌داند.
3. **محدودیت‌های هاست در پردازش طولانی**: در هاست‌های اشتراکی با محدودیت سخت‌گیرانه زمان اجرای PHP (`max_execution_time=30s`)، عملیات‌های گروهی با حجم بسیار زیاد باید در قالب تکه‌های کوچک پردازش شوند.
4. **نیازمندی دامنه عمومی برای وب‌هوک‌ها**: دریافت وب‌هوک‌های لحظه‌ای از ووکامرس مستلزم این است که سامانه CRMWP بر روی یک آدرس اینترنتی عمومی معتبر مستقر باشد (بر روی `localhost` وب‌هوک‌های ورودی دریافت نمی‌شوند مگر از ابزارهای تونل مانند ngrok استفاده شود).

## پرسش‌های متداول

### آیا این نرم‌افزار یک پلاگین وردپرس است؟
خیر. این سامانه یک اپلیکیشن کاملاً مستقل (Standalone Web Application) است و هیچ کدی در وردپرس نصب نمی‌شود.

### آیا برای کار با این سامانه، باید وردپرس روی همین سرور نصب باشد؟
خیر. سامانه می‌تواند روی یک سرور یا ساب‌دامین کاملاً مجزا از فروشگاه ووکامرس میزبانی شود و از طریق بستر شبکه با API فروشگاه تبادل اطلاعات کند.

### آیا سامانه مستقیماً به دیتابیس وردپرس متصل می‌شود؟
خیر. تحت هیچ شرایطی اتصالی به دیتابیس وردپرس برقرار نمی‌شود؛ تمامی اطلاعات از طریق لایه استاندارد و امن WooCommerce REST API جابجا می‌گردند.

### آیا محصولات متغیر و تنوع‌ها (Variations) پشتیبانی می‌شوند؟
بله. کاتالوگ محصولات به طور کامل از کالاهای متغیر و مشاهده و ویرایش تک‌تک تنوع‌ها پشتیبانی می‌کند.

### وضعیت ویرایش گروهی برای تنوع‌ها چگونه است؟
کاملاً پیاده‌سازی شده است. شما می‌توانید دامنه عملیات گروهی را روی «فقط والد»، «فقط تنوع‌ها» یا «هر دو» قرار داده و قیمت‌ها یا موجودی انبار را با پیش‌نمایش و کنترل تکرار به صورت گروهی بروزرسانی نمایید.

### آیا برای اجرای نسخه پروداکشن به Node.js نیاز است؟
خیر. کلیه فایل‌های فرانت‌اند قبل از استقرار بیلد شده و در بسته نهایی قرار می‌گیرند. سرور پروداکشن صرفاً به PHP 8.2+ و دیتابیس نیاز دارد.

## نکات و خط‌مشی امنیتی

* **گزارش آسیب‌پذیری**: در صورت کشف هرگونه باگ یا ریسک امنیتی، لطفاً به مستندات [SECURITY.md](file:///d:/crmwp/SECURITY.md) مراجعه کرده و موضوع را مستقیماً با تیم توسعه در میان بگذارید.
* **عدم انتشار فایل `.env`**: هرگز فایل حاوی مقادیر واقعی `APP_SECRET` و رمزهای پایگاه‌داده را در مخازن عمومی قرار ندهید.
* **کلیدهای ووکامرس**: کلیدهای `Consumer Secret` ووکامرس در حکم دسترسی به کل فروشگاه هستند؛ سامانه این کلیدها را رمزنگاری می‌کند اما حفظ دسترسی فیزیکی به سرور بر عهده مدیر سیستم است.
